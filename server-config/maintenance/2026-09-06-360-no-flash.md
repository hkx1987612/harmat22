## Defects And Repair

The old viewer used `decoding="async"` and hid every previous image when a target's load flag was set. There was no explicit decode barrier. The error callback also set that success flag; a failed image could therefore hide the last usable view. An older pending load could override a newer already-loaded selection.

The revised viewer waits for successful decoding, draws into one retained full-resolution canvas, and never clears or resizes a painted surface between frames. Drawing failure retains the previous view and its hitboxes. Image/decode errors are not marked successful. Completed requests only update the currently requested frame. Rotation advances from the pending destination so a slow or failed neighbor does not permanently trap the arrow control. Existing image preloading cadence and asset resolution are preserved.

Reference: [MDN HTMLImageElement.decode](https://developer.mozilla.org/en-US/docs/Web/API/HTMLImageElement/decode) describes avoiding empty-image presentation by waiting for decode before replacement.
